## Harness ที่ยังต้องสร้างหลัง gate ผ่าน

isolated PostgreSQL + Auth/FileVersion/scan/workflow/outbox/business services ของโครงการจริง, central TEST fixtures deterministic และ rule/form version ที่อนุญาต DEMO, pin tool/browser/dependency ตามแผนใหม่ที่ได้รับอนุมัติ [MASTER ข้อ 2](../../00_MASTER_PROMPT.md), server clock/fault hooks เฉพาะ test ไม่เปิด production ไม่มี mock successful responses หรือ engine/table สำรอง

ก่อน full load ทำ correctness smoke และ warmup ตาม profile แยกจาก measured samples; bound request timeout/run duration/maximum files/queue และหยุดเมื่อ invariant เสีย/ข้อมูลรั่ว/OOM/บริการไม่พร้อม บันทึก failures/retries ไม่ลบ slow samples ใช้ steady workload รายเดี่ยวก่อนผสมเพื่อแยก bottleneck; planned acceptance ต้องรันซ้ำอย่างน้อย 3 รอบและรายงานแต่ละรอบ ไม่รวม sample ข้าม config เป็น p95 เดียว

ใช้ original events/source counters เป็น oracle ไม่ให้ production helper สร้าง expected จากตัวเอง ห้ามลด server authorization/scan/ACL/transaction เพื่อผ่าน latency ห้ามเพิ่มวงเงินหรือผลิตผลทางการด้วย TO VERIFY ไม่สร้างผู้ใช้หรือแก้ข้อมูล production

ขณะนี้ executable business load scripts, browser checks, private cache A/B และ worker memory tests ยังไม่ถูกสร้าง/รัน เพราะ prerequisite68และowner servicesไม่พร้อม ชุด probeชั่วคราวทำได้เฉพาะ GETหน้าstarter+403 no-store ไม่ใช่ harness ที่ใช้รับรองความจุ
