# คู่มือคำขอและการแก้คำสั่ง — ฉบับเตรียมระบบ 4

รุ่น 0.1 | 4 ตุลาคม 2569 | **Proposal / BLOCKED — ยังไม่มีหน้าและบริการที่ทำตามคู่มือนี้ได้จริง**

อ่าน [UAT_SYSTEM_04](UAT_SYSTEM_04.md) และแบบ [คำขอ30](ORG_CENTER_REQUESTS.md), [wizard31](REQUEST_WIZARD.md), [review32](REQUEST_REVIEW.md), [วันมีผล33](REQUEST_EFFECTIVE_RULES.md) ใช้คู่มือนี้ตรวจความครบก่อนimplementation ไม่ใช้เป็นคำสั่งทางการหรือหลักฐานว่าเปิดบริการแล้ว

## 1 คำที่เจ้าหน้าที่ต้องแยก

| คำ                      | ความหมายเมื่อมีimplementation                        | สิ่งที่ห้ามสรุปแทน                                       |
| ----------------------- | ---------------------------------------------------- | -------------------------------------------------------- |
| draft / returned        | กำลังร่างหรือถูกส่งกลับแก้                           | ยังไม่อนุมัติและไม่เปลี่ยนทะเบียน                        |
| submitted / reviewing   | ส่งแล้วหรือกำลังตรวจรุ่นที่ส่ง                       | กำลังขอไม่เท่ากับสถานะหน่วยงาน/สนาม                      |
| approved                | คำขอรุ่นที่ตรวจผ่านตามอำนาจ                          | ไม่แปลว่าถึงวันหรือactivationสำเร็จ                      |
| effective               | activationและทะเบียนเปลี่ยนจริงผ่านguards            | ส่งnotificationสำเร็จไม่ใช่เงื่อนไขให้เป็นeffective      |
| rejected / cancelled    | เรื่องจบรอบโดยไม่มีeffectใหม่                        | ไม่ลบเรื่อง/เหตุผล/หลักฐาน และไม่ล้างคำสั่งeffectiveเดิม |
| correction / revocation | เรื่องใหม่ผ่านตรวจเพื่อแก้หรือเพิกถอนคำสั่งต้นเรื่อง | ไม่กดundoทุกอย่างหรือลบstatus eventเก่า                  |
| TO VERIFY / DEMO        | กฎยังขาดหลักฐาน/ตัวอย่างทดลอง                        | ไม่ใช่แบบ อำนาจ หรือข้อมูลทางการที่ยืนยันแล้ว            |

วันที่แสดง พ.ศ. แต่ข้อมูลเก็บมาตรฐาน ใช้วันไทยจากconfig แยกวันขอมีผล วันมีผลจริง เวลาบันทึกและเวลาส่งแจ้งเตือน ตัวอย่างสมมติต้องติดป้าย “ข้อมูลทดลอง — ไม่ใช่คำสั่งทางการ” ทุกหน้ารายงาน/print/exportที่ใช้DEMO

## 2 ผู้ยื่นเตรียมและติดตาม

1. เข้าใช้บัญชีกลาง ตรวจสังกัดและcurrentassignment เลือกหนึ่งใน10ประเภท จัดตั้ง/ยุบสำนักเรียนหรือสำนักศาสนศึกษา และเปิด/ปิด/ย้ายสนามนักธรรมหรือธรรมศึกษา ไม่สร้างทะเบียนหรือloginเพิ่ม
2. เลือกtargetจากสิทธิ์จริง ระบุรอบ/ปี/ประเภทให้ตรง หากไม่มีแม่บทหรือกฎให้ประสานผู้รับผิดชอบ ไม่เดารหัสหรือแก้target_idเพื่อเข้าข้อมูลอื่น
3. กรอกเหตุผล ที่ตั้งใหม่เมื่อจำเป็น วันขอมีผลและหลักฐานผ่านเอกสารกลาง รอscan/ACLไม่ใช้ไฟล์quarantine preview/download/อนุมัติ
4. บันทึกร่าง รอserverreceiptก่อนถือว่าบันทึกแล้ว เครือข่ายขาดหรือconflictให้โหลดข้อมูลตามสิทธิ์และเทียบใหม่ ไม่เพิ่มrevisionเองเพื่อทับงานคนอื่น
5. ตรวจทานก่อนส่ง หากยุบ/ปิดมีผู้สมัคร/หน้าที่/จัดส่งค้าง แนบแผนและผู้รับรองตามpolicy ไม่ลบข้อมูลเพื่อทำให้รายงานเป็นศูนย์
6. เมื่อreturnedแก้ในเรื่องเดิมแล้วresubmitรุ่นใหม่ ไม่เปิดเรื่องซ้ำจากreload/timeout คำตัดสินรุ่นเก่าไม่อนุมัติรุ่นใหม่
7. ติดตามด้วยบัญชี/สิทธิ์ของตน แยกสถานะคำขอจากทะเบียนและnotification เลขtrackingไม่สิทธิ์อ่านเรื่อง/เหตุผล/ไฟล์ของผู้อื่น

## 3 ผู้ตรวจและผู้อนุมัติ

1. เปิดคิวตามscope/สาย/พื้นที่/ช่วงมอบหมาย ตรวจรุ่นที่ส่งและหลักฐานที่ได้รับอนุญาต ผู้ดูแลเทคนิคไม่รับอำนาจธุรกิจโดยปริยาย
2. ตรวจbefore/afterและผลกระทบ4ด้าน: ผู้สมัคร รอบสอบ บุคลากร และจัดส่ง Missingadapterหรือsourceไม่ครบให้NOT_READY ไม่เรียก0ว่าไม่มีผลกระทบ
3. ผู้ตรวจส่งกลับหรือให้ความเห็นพร้อมเหตุผล ผู้อนุมัติอนุมัติ/ปฏิเสธตามgrant/กฎ/delegationที่ยังมีผล ผู้สร้างหรือผู้มอบอำนาจที่เป็นmakerไม่อนุมัติเรื่องตน
4. หากconflictให้โหลดรุ่นใหม่และตรวจอีกครั้ง ไม่autoapproveใหม่ ผู้อนุมัติสองคนแข่งต้องหนึ่งชุดคำตัดสิน ไม่ใช่ให้ทั้งคู่ผ่าน
5. อนุมัติแล้วให้ตรวจวัน/เงื่อนไขค้างก่อนactivation หากdueแต่guardไม่ผ่านแสดงรอดำเนินการ/ติดเงื่อนไข ไม่บอกว่าปิดสนามแล้วเพราะกดapprove
6. ใช้แผนที่ผ่านตรวจให้ownerจัดการผู้สมัคร/หน้าที่/ส่งเอกสาร ไม่โยกคน/เลือกผู้รับข้อสอบ/คืนสิทธิ์จากที่อยู่เอง และไม่แก้snapshotปีเก่า

## 6 ปัญหาและการรายงาน

403/ไม่พบเรื่อง: ตรวจcurrentassignmentแล้วแจ้งรหัสปัญหาไม่คัดPII; conflict: หยุดตัดสินและอ่านรุ่นใหม่; ไฟล์ไม่พร้อม: รอscan/ตรวจACL; impactไม่พร้อม: ติดต่อownerตามหน้าที่; notificationล่าช้า: อ่านregistry/historyจริงไม่ส่งคำสั่งซ้ำ; dueactivationค้าง: รายงานguard/deadletterตามสิทธิ์ ไม่แก้DB/สถานะตรง

ส่งsupportเฉพาะsafeerrorcode/correlation/version/วันเวลาและประเภทงาน ไม่มีpassword/token/recoverycode/เหตุผลส่วนตัวเต็มหรือไฟล์แนบในpubliclog ปัจจุบันยังไม่มีหน้า/actions/jobตามคู่มือ ทุกUAT34 NOT RUN ต้องตรวจรับ30–33และruntimeก่อนใช้จริง บท35ยังไม่เริ่ม
