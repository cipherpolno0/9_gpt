# เส้นทางใช้งานร่วม — เว็บไซต์กองบริหารทะเบียนและวัดผล

บท 03 | รุ่นเอกสาร 1.3 | 3 ตุลาคม 2569 (2026-10-03)

## 1 ความหมายและฐานการออกแบบ

UX flow คือขั้นตอนที่ผู้ใช้เดินตั้งแต่เข้าเว็บจนจบงาน พร้อมทางออกเมื่อมีปัญหา ใช้ [ผังหน้า](SITEMAP.md), [แบบร่าง](WIREFRAMES.md) และสิทธิ์ P01–P11 จาก [PERMISSIONS](PERMISSIONS.md) ทุก URL เป็นข้อเสนอการออกแบบตามบัญชีหน้า PG ไม่ใช่ route ที่ deployแล้ว

ผู้ใช้อนุมัติแผนบท03ด้วย “ตกลง” วันที่3 ตุลาคม2569 งานนี้สร้างเอกสารและต้นแบบออฟไลน์ ไม่สร้าง backend/Authจริง แบบร่างเปิดได้ที่ [chapter03.html](wireframes/chapter03.html) การกดในต้นแบบเปลี่ยนข้อมูลสมมติในหน่วยความจำ ไม่มีการส่งบัญชี ไฟล์ คำขอ หนังสือ หรือเงินออกไปจริง

## 3 เส้นทางหลัก 4 กลุ่มตั้งแต่เข้าเว็บจนจบงาน

### FLOW-01 บุคคลทั่วไปค้นผลสอบรายปี

| ขั้น | หน้า/แบบร่าง | ผู้ใช้ทำอะไร | สิ่งที่ระบบต้องทำ/ผล | ทางแก้และสิทธิ์ |

| 1 | PG-01 / WF-01 | เลือก “สอบธรรมสนามหลวง” | ไปPG-05→“ค้นผลสอบ”PG-06; ไม่เปิดapp | P09; อ่านเฉพาะข่าวที่เผยแพร่ |
| 2 | PG-06 / WF-06 | เลือกปีการศึกษา2569 ประเภท ระดับ และเงื่อนไขค้นที่นโยบายอนุญาต | ค่าเริ่มต้นยังไม่ค้น; กดค้นแล้วโหลดreleaseปีที่เลือก | ไม่ใช้เลขประชาชน/วันเกิด/เบอร์ส่วนตัวเป็นตัวกรองสาธารณะ; Q008รับรองฟิลด์จริง |
| 3 | PG-06 / WF-06 | อ่านรายการทดลอง | แสดงปีที่ค้นและรุ่นประกาศทุกครั้ง; ไม่ปะปน2568หรือคะแนนฝึก | draft/ถอนเผยแพร่ไม่คืนข้อมูล; ไม่มีผลแสดงS-Eและปุ่มแก้ตัวกรอง |

## 8 วิธีตรวจรับและบันทึกหลักฐาน

1. ตรวจFLOW-01–04กับPGในSITEMAPและWFในWIREFRAMES มีทางเริ่ม ผลจบ errorและกลับแก้ทุกเส้นทาง
2. เปิดต้นแบบ เลือกหน้า/สถานะ แล้วเดิน4เส้นทางจำลองตามคำแนะนำในWIREFRAMES บันทึกว่าผ่านเฉพาะส่วนที่มีการจำลองจริง
3. ใช้keyboardเปิด/ปิดเมนูมือถือ ย้อนขั้น และลิงก์แก้field; ทดสอบ320/375/768/1280px ไม่มีหน้าเลื่อนแนวนอนนอกกรอบตาราง
4. ตรวจว่าปุ่มcontact/download/loginพาไปต้นทางเดียว ไม่มีการส่งข้อมูลจริง; nativeAPI/RLS/scan/workerยังNOT RUN
5. เก็บผลในPROGRESS: walkthroughเอกสาร, prototypecheckและruntimeแยกกัน ผู้ใช้จริง/assistivetech/UATยังรอQ018/Q021 ไม่เปลี่ยนข้อเสนอเป็นรับรองเพราะกดต้นแบบผ่าน
