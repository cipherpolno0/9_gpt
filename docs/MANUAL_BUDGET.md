# คู่มือเตรียมใช้งานงบประมาณ — บท 46

รุ่น 0.1 | 7 ตุลาคม 2569 (2026-10-07) | **Proposal / BLOCKED — ขั้นตอนนี้ยังไม่มีหน้าจอหรือบริการใช้งานจริง**

ใช้คู่มือนี้ตรวจความต้องการและเตรียม UAT ตาม [UAT_SYSTEM_06](UAT_SYSTEM_06.md) ไม่ถือว่าทำธุรกรรมได้แล้ว ตัวเลข รหัส ผู้กระทำและเอกสารใน [coverage-plan](../tests/fixtures/system06/coverage-plan.json) เป็นสมมติ ไม่เป็นบัญชีจริง ไม่มี login หรือทะเบียนหน่วยงานแยกจากเว็บไซต์หลัก

## 1 เลือกบริบทก่อนทำรายการ

1. เข้าบัญชีเดียวจาก provider ที่ตั้งค่า ตรวจหน้าที่ หน่วยงาน แหล่งเงิน และช่วงมอบหมายปัจจุบัน ไม่มีสิทธิ์ให้หยุดและขอผู้มีอำนาจตรวจ ไม่เปลี่ยน URL/body/query org_id เพื่อเลือกพื้นที่อื่น
2. เลือก FiscalYear และ currency ก่อนเลือกโครงการ ปีการศึกษาอาจเชื่อมหลายปีงบ เลขปีเท่ากันไม่หมายถึงปีชนิดเดียวกัน หน้ารายงานต้องระบุช่วงเวลา รุ่นและความสดของข้อมูล
3. ตรวจ policy/source version และเอกสารยืนยัน ผู้เสนอ ผู้ตรวจ ผู้อนุมัติเป็นคนละคนตามบท 44 ผู้ดูแลเทคนิคไม่เพิ่มสิทธิ์อนุมัติจากชื่อฝ่าย
4. แสดงวันที่ พ.ศ. ใช้วันตัดรอบ Asia/Bangkok; เก็บวันมาตรฐานและแยกวันมีผลจากวันบันทึก ห้ามใช้เวลาบนเครื่องผู้ใช้เปลี่ยนวันอนุมัติหรือเปิดงวด

## 2 ร่างแผน เสนอและจัดสรร

กรอกโครงการ รายการ แหล่งเงิน ค่าใช้จ่ายและรายได้คาดการณ์แยกกัน รายได้คาดการณ์ไม่เป็นงบพร้อมใช้ บันทึกร่างแล้วตรวจ requirements/หลักฐานก่อนส่ง รายการถูกส่งกลับแก้ในเรื่องเดิมพร้อม revision; conflict ให้โหลดรุ่นล่าสุดและตรวจความต่าง ไม่แก้ทับเงียบ ๆ

ผู้ตรวจและผู้อนุมัติตรวจขอบเขต วงเงินสะสม และ delegation ณ วันที่ตัดสิน การอนุมัติแผนไม่สร้างยอดจัดสรรเองจนโพสต์ allocation ตามขั้นตอนที่รับรอง แผนที่ยังไม่อนุมัติใช้จองไม่ได้ การเพิ่ม ลด โอน ใช้คำขอใหม่พร้อมเหตุผลและหลักฐาน ไม่แก้ยอดเดิมทับ อ่าน [BUDGET_PLANNING](BUDGET_PLANNING.md), [BUDGET_APPROVALS](BUDGET_APPROVALS.md)

## 3 จอง ผูกพัน รับรองและบันทึกจ่าย

1. จองเฉพาะงบที่มีผลและอยู่ในงวดที่เปิด บริการตรวจยอดปัจจุบันใน transaction ไม่ใช้ตัวเลขรายงานเก่าหรือยอด client เป็นวงเงิน เมื่อเกิด conflict/งบไม่พอให้ตรวจใหม่ ไม่เปลี่ยน key เพื่อกดซ้ำหลบข้อจำกัด
2. เมื่อเกิดภาระที่มีหลักฐาน เปลี่ยนยอดจองเป็นภาระใน transaction เดียว R ลดและ U เพิ่ม ไม่เพิ่มภาระพร้อมคงยอดจองเดิม
3. เสนอเบิกจากภาระหรือประเภทรายจ่ายที่ policy อนุญาต ตรวจ issuer/invoice reference, งวด, ยอดจ่ายรวม, unpaid claims และยอด voucher อย่าแบ่งงวดเพื่อหลบวงเงิน ผู้สร้างห้ามตรวจ/อนุมัติของตนเองตาม flow44
4. แนบเอกสารผ่านบริการกลาง private/quarantine ตรวจ MIME จากเนื้อหา ขนาด ชนิดและ scan เอกสารยังไม่ผ่านห้าม preview/download/ใช้อนุมัติ การ CLEAN ไม่แทนความถูกต้องของเนื้อหา/อำนาจผู้ลงนาม รุ่นเอกสารใหม่ต้องตรวจใหม่
5. รับรองเบิกทำให้ C เพิ่มแต่เป็นส่วนหนึ่งของ U ไม่ลดคงเหลือซ้ำ บันทึกจ่ายต้องอ้างคำรับรองและหลักฐานที่ถูกต้อง U และ C ลดพร้อม P เพิ่มเฉพาะยอดที่จ่าย การบันทึกนี้ไม่โอนเงินธนาคาร
6. เครือข่ายขาดหลังส่งให้ใช้ idempotency key/payload เดิมและตรวจผลเดิม ไม่สร้างคำขอใหม่เอง ถ้าสิทธิ์ถูกถอนระหว่าง retry ต้องถูกปฏิเสธแม้มีผลเดิมอยู่

ตัวอย่าง A100000/R20000/U0/P0 เหลือ80000 → เปลี่ยนเป็น R0/U20000 เหลือ80000 → จ่าย5000 เป็น U15000/P5000 เหลือ80000 อ่าน [BUDGET_BALANCE_FORMULA](BUDGET_BALANCE_FORMULA.md), [DISBURSEMENT_WORKFLOW](DISBURSEMENT_WORKFLOW.md)

## 4 ปลด โอน และแก้รายการผิด

ปลดเฉพาะยอดจองหรือภาระคงค้างที่ได้รับอนุมัติ ไม่ปลดเงินที่จ่ายแล้วหรือส่วนที่มี claim/certification ขัดกัน โอนงบต้องตรวจทั้งต้นทางและปลายทาง ข้อจำกัดแหล่งเงินและงวด; สอง legs ต้องสำเร็จหรือ rollback พร้อมกัน

รายการโพสต์แล้วห้ามลบหรือแก้โดยตรง ขอ correction/refund/cancellation/reversal ใหม่ ระบุ original event, เหตุผล, หลักฐาน, ผลกระทบ, ผู้ตรวจและผู้อนุมัติ การบันทึกจ่ายผิดกับคืนเงินจริงเป็นคนละเหตุ อย่าเพิ่ม U/C หรือคืนสิทธิ์เบิกโดยเดา ตรวจ downstream และงวดก่อนกลับรายการ คงเลขอ้างอิงและประวัติต้นทาง อ่าน [FINANCE_REVERSALS](FINANCE_REVERSALS.md)

## 5 รายงาน กระทบยอดและปิดงวด

เลือกวันที่อ้างอิงและโหมดรายงาน ดู A/R/U/P/C/V ตาม FiscalYear/แหล่งเงิน/โครงการ/หน่วยงาน หน้าจอ Excel และ HTML print→PDF ต้องใช้ report version/manifest เดียวกัน ชื่อหน่วยงานปีเก่ามาจาก snapshot/version ไม่ตามชื่อใหม่ รายงาน restated ต้องมีเหตุผลและลิงก์รุ่นเดิมตามสิทธิ์

Projection ช้าต้องแสดง last processed/watermark; mismatch ให้หยุดรับรองหรือปิดงวดและแจ้งตรวจ ไม่ปรับ ledger เป็นศูนย์ ไม่เขียนยอด projection ทับเพื่อให้รายงานดูตรง งบทดลองระบบคือ opening + movement = closing ของ buckets ยังไม่ใช่งบทดลองบัญชีทางการ

ก่อนปิดงวดตรวจ ledger/ต้นเรื่อง/หลักฐาน/outstanding รายการค้าง/manifest และ policy ที่ยืนยัน ไม่ล้าง R/U/C เพื่อปิดงวด ผู้อนุมัติตรวจรุ่นที่ seal หากมี posting ระหว่างตรวจต้องแจ้ง conflict ให้ตรวจรุ่นใหม่ งวดปิดห้ามเขียนย้อนวัน/import/reversal/worker โดยข้าม gate

เปิดงวดหรือปรับปรุงหลังปิดต้องคำขอและคำอนุมัติใหม่ตาม policy มีเหตุผล/เอกสาร คง close/report รุ่นเก่า ไม่สร้าง carry-forward หรือจัดสรรปีใหม่จากยอดค้างเอง อ่าน [BUDGET_RECONCILIATION](BUDGET_RECONCILIATION.md), [BUDGET_PERIOD_CLOSE](BUDGET_PERIOD_CLOSE.md)

## 6 การส่งออก การตรวจสอบและแจ้งปัญหา

ข้อมูลการเงินอยู่ private ตรวจสิทธิ์อีกครั้งเมื่อขอ export, worker เริ่มงาน และดาวน์โหลด ไฟล์ใช้เอกสารกลาง ไม่ใส่ public folder ผู้หมดมอบหมายไม่ดาวน์โหลดไฟล์เก่าผ่าน ID/object key ได้ หากต้อง revoke การอ่านครั้งถัดไปใช้ gateway ตรวจ ACL; ไม่อ้างว่าเรียกคืนไฟล์ที่ผู้ใช้ได้รับแล้วได้ทันที

ลิงก์ไปพัสดุ/สารบรรณใช้ต้นทางกลางและสิทธิ์ปลายทางเมื่อโมดูลพร้อม การเปิดรายงานหรือลิงก์ไม่สร้างจองงบ จ่าย รับสินค้า หรือส่งหนังสือ ถ้าโมดูลยังไม่พร้อมให้แสดงสถานะ ไม่สร้างธุรกรรมทดแทน

ผู้ตรวจสอบย้อน event/decision/evidence/hash/receipt/report version ตาม scope แจ้งปัญหาด้วย correlation, รุ่น, บริบทและขั้นตอนที่ลดข้อมูลผ่านช่องทางกลางที่เจ้าของยืนยัน ห้ามส่ง password/token/recovery code/ข้อมูลส่วนตัว/หลักฐานเงินจริงเต็มชุดลง log หรือ issue สาธารณะ ยังไม่มีช่องทางหรือชื่อเจ้าหน้าที่จริงที่ระบุในคู่มือนี้
